# Synthetic PDF: focused final page and smaller dense regions

Date: 2026-09-29 (America/Bogota). All calls used the fixed, invented five-page PDF generated by `scripts/eval/pdf-statements/fixture.ts`. No personal statement, production row, or document image was used. The same Qwen3 VL 30B vision adapter and `provider.data_collection: deny` setting were used throughout. These are image calls, not a deployment or a product PDF upload.

The earlier [three-region result](2026-09-29-pdf-synthetic-tiles-live.md) recovered the dense page twice but missed or misread both final-page rows. Three bounded approaches were considered: crop the sparse final page to its visible content, split the eight-row middle dense region, or escalate to Qwen 235B. The first two were chosen because they retain the cheaper 30B path and keep the image regions small. The 235B full-page probe had already truncated at 2,048 output tokens and cost more.

`--focus-final` substitutes a 935 × 265 px crop of page 5 for its whole-page image. The crop contains both final rows completely, as checked against the generated PDF word boxes. Dense page 4 now has four regions rather than three; the middle eight-row region is split into five-row and four-row regions. Overlap references `REF-405`, `REF-409`, and `REF-412` are attributed to their original page and region and reconciled only when their values agree. The full run sends three ordinary pages and five crops, for eight image calls. Every region must complete for the score to pass.

Command: `npm run eval:pdf-synthetic -- --live --tile --focus-final`, with the ignored local OpenRouter key loaded into the environment. The command prints only counts, references, timings, tokens, and billed USD; it does not print the key, raw images, or model prose. A nonpassing run exits with code 2.

All four run totals were reported by OpenRouter and add to $0.01024287. A separate diagnostic call on only the five-row middle region returned its five exact rows for $0.00039741; it is not included in the table's full-document totals. The observed cost is specific to this tiny synthetic fixture and current provider responses. It does not estimate scanned statement cost or bound a real user's monthly spend.

The single 21/21 result proves that the page/region plumbing can produce a complete extraction on this fixture. The surrounding failures show the model output is not repeatable enough for the required two independent clean runs. The errors were content-quality failures despite successful responses and complete cost metadata, so retrying until a result matches the fixture would overfit to this known oracle and would not be a safe production strategy. The synthetic PDF has a text layer and one simple layout; scans, other statement formats, more than 50 rows, and rendering in the deployment runtime remain unverified.

Keep PDF upload disabled. Before changing that gate, evaluate diverse labelled synthetic and scanned layouts, make row-level visual review mandatory, and design a verification path that does not assume known answer rows. No OCR result here authorizes transaction creation or database writes.
