# Reviewed Shortcut event time

Some bank notifications arrive after the purchase. The inbox's `received_at` is the immutable message receipt instant, so a reviewer must be able to record the original transaction instant separately when the message or their records support it. The pending Bancolombia notice described in WEB-34 has a 20-minute delay.

Migration `20260929000180_shortcut_reviewed_event_time.sql` extends the existing four-argument `confirm_shortcut_transaction` RPC without changing its caller signature. The usual six-field review remains valid and retains the existing receipt-based time. An optional reviewed event requires two additional fields in the same immutable review payload: `event_at` (RFC 3339 with seconds and an explicit offset) and `event_time_confirmed: true`. The signed-in reviewer enters the original local date and time and confirms it against the SMS or their records. The server never infers it from `received_at`.

The SQL function rejects incomplete or malformed event reviews, a Colombia-local event date different from the reviewed transaction date, an event more than five minutes after the message receipt, or one more than 31 days earlier. It keeps the original `received_at` in the inbox and `shortcut_received_at` in `parsed_data`, stores the reviewed instant as `shortcut_event_at`, uses its Colombia-local time in the transaction, and copies the event instant into the append-only decision snapshot. An identical retry replays the original decision; a different event time conflicts. Candidate review, owner and category checks, quota accounting, account balance updates, and hard-erasure behavior remain in the same atomic function.

Deploy the database migration before the web route and form. The web form keeps the event time blank by default, requires explicit confirmation if entered, and passes the original instant through the existing creation route. Cross-day notifications require the reviewer to set the transaction date to the event's date. Existing transactions are not rewritten. Validate the delayed pending notice through the signed-in UI after both deployments, including its account, category, duplicate candidates, and source text.

PGlite tests cover a 20-minute delay, cross-day receipt, compatibility with six-field creation, invalid/unconfirmed timestamps, and replay. The web route and page tests cover validation, explicit confirmation, and payload propagation. Live PostgreSQL concurrency and production deployment remain release checks.
