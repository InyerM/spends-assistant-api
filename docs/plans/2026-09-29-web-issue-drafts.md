# Web-first issue drafts

These are local issue drafts for review, not published GitHub issues. The web app and shared Worker/database contracts are the first release target. Mobile parity follows only after those contracts are stable. A check mark means a local implementation exists; it does not mean production release approval or a real-data quality result.

## Release 1: safe capture and reviewed matching

- [x] **WEB-01 — Replace Gemini with measured OpenRouter text and image calls.** Acceptance: text requests use DeepSeek V4.1 Flash with zero-retention routing; image requests use Qwen3 VL 30B with `data_collection: deny`; a 235B escalation is explicit; returned token/cost telemetry is recorded; the existing request-count quota remains and USD 10 per person per month is only a planning estimate. Evidence: `src/ai/openrouter.ts`, `src/ai/vision.ts`, `docs/evaluations/2026-09-28-openrouter-synthetic.md`.
- [x] **WEB-02 — Create a private image review inbox.** Acceptance: owner-scoped PNG/JPEG/WebP upload, document classification, multiple draft observations, no automatic financial write, and explicit extraction failure. Evidence: `supabase/migrations/20260929000010_document_inbox.sql`, web `/documents`, and Worker `/vision/extract`.
- [x] **WEB-03 — Make document matching explicit and auditable.** Acceptance: read-only existing-transaction suggestions; owner and amount checks; idempotent accept/reject decision; reviewed observation immutability; no account balance mutation. Evidence: `supabase/migrations/20260929000060_document_confirmation.sql`, web `/api/documents/[id]/decisions`, and SQL tests.
- [x] **WEB-04 — Restrict extraction persistence to the server.** Acceptance: an authenticated client cannot submit OCR results or failures directly; the server must provide owner and current claim token; the migration and web route must be released together. Evidence: `supabase/migrations/20260929000070_document_provenance.sql` and web `/api/documents/[id]/extract`.
- [x] **WEB-05 — Capture historical Shortcut messages without duplicates.** Acceptance: private bounded batch intake, original timestamp and raw text preserved, idempotent replay, export/review, and read-only candidate search. Evidence: `supabase/migrations/20260929000030_shortcut_inbox.sql` and web `/transactions/shortcut-inbox`.
- [x] **WEB-06 — Confirm an existing transaction from a Shortcut item.** Acceptance: explicit owner-scoped, replay-safe acknowledgement; independently received notices can refer to the same real transaction; no financial mutation; hard deletion behavior is tested. Depends on WEB-05. Evidence: `supabase/migrations/20260929000080_shortcut_match_ack.sql`, web `/transactions/shortcut-inbox`, and six PGlite tests. Correction after a mistaken acknowledgement remains a separate review action.
- [ ] **WEB-07 — Create a reviewed new transaction from an unmatched Shortcut item.** Acceptance: require a deliberate category/account/amount/date confirmation, recheck duplicates within the database transaction, write the transaction and balance exactly once, and keep the original message plus decision provenance. Depends on WEB-06 and the existing atomic import pattern. No automatic creation from an ambiguous Nequi recipient.
- [x] **WEB-08 — Make CSV confirmation atomic.** Acceptance: owner-scoped idempotent import, recheck existing and within-batch duplicates at commit time, and one balance update per accepted row. Evidence: `supabase/migrations/20260929000020_atomic_csv_import.sql` and web import tests.
- [ ] **WEB-14 — Make the existing AI request quota concurrency-safe.** Acceptance: text and OCR both consume the same request-count allowance through one atomic database operation, with concurrent free-plan calls unable to exceed the configured count; pro-plan behavior remains unchanged. The OCR route now uses `UsageService.incrementAiParses`, but that existing read-then-write implementation can race under simultaneous requests. This is a request-count control, not a USD spending cap.

## Release 2: document coverage and financial context

- [ ] **WEB-09 — Benchmark and implement multi-page PDF statements.** Acceptance: synthetic page/row coverage and attribution gate passes before UI exposure; private bounded rendering, per-page retry state and page evidence, explicit overflow; no silent truncation. Depends on WEB-02–04. See `docs/plans/2026-09-28-multipage-pdf-statement-gate.md`.
- [ ] **WEB-10 — Evaluate semantic retrieval before pgvector backfill.** Acceptance: compare labeled Spanish receipt/Nequi candidate recall with exact matching, confirm provider privacy, then implement owner-scoped versioned embeddings and bounded search only if useful; relational status and exact amount remain authoritative. Depends on WEB-03. See `docs/plans/2026-09-28-document-vector-search.md`.
- [x] **WEB-11 — Add reviewed investment and loan journals.** Acceptance: owner-scoped Tyba/Binance positions and Lulo/Bancolombia loans with exact decimal amounts, replay safety, dated valuations/payment allocations, and no implicit impact on accounts or net worth. Evidence: migrations `20260929000040_manual_investments.sql` and `20260929000050_manual_loans.sql`, web `/investments` and `/loans`.
- [ ] **WEB-12 — Reconcile wealth with cash and net worth.** Acceptance: real opening statements and loan terms are reviewed, transfers and repayments do not double count, FX valuation is explicit, and each derived balance can be traced to ledger entries. Depends on WEB-11 and user-supplied figures.
- [ ] **WEB-13 — Review historic transaction quality.** Acceptance: present the private 1,516-row audit and 72 review signals, collect labeled corrections, evaluate prompt/category accuracy, and apply only approved edits with a reversible change log. Depends on the user's review. See `docs/audits/2026-09-28-transaction-quality-audit.md`.

## Release gate and mobile handoff

Before publishing web or database changes, run full tests, type checks, lint, web build, Worker dry run, SQL ownership/replay checks, and verify remote migration history with a backup. Obtain explicit approval for production migration and deployments. After the released web flows are stable, open mobile parity issues for document review, Shortcut intake, investment positions, and loans. Do not alter the existing mobile working tree during this web phase.
