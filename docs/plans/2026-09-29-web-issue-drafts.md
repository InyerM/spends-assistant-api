# Web-first issue drafts

These are local issue drafts for review, not published GitHub issues. The web app and shared Worker/database contracts are the first release target. Mobile parity follows only after those contracts are stable. A check mark means a local implementation exists; it does not mean production release approval or a real-data quality result.

## Release 1: safe capture and reviewed matching

- [x] **WEB-01 — Replace Gemini with measured OpenRouter text and image calls.** Acceptance: text requests use DeepSeek V4.1 Flash with zero-retention routing; image requests use Qwen3 VL 30B with `data_collection: deny`; a 235B escalation is explicit; returned token/cost telemetry is recorded; the existing request-count quota remains and USD 10 per person per month is only a planning estimate. Evidence: `src/ai/openrouter.ts`, `src/ai/vision.ts`, `docs/evaluations/2026-09-28-openrouter-synthetic.md`.
- [x] **WEB-02 — Create a private image review inbox.** Acceptance: owner-scoped PNG/JPEG/WebP upload, document classification, multiple draft observations, no automatic financial write, and explicit extraction failure. Evidence: `supabase/migrations/20260929000010_document_inbox.sql`, web `/documents`, and Worker `/vision/extract`.
- [x] **WEB-03 — Make document matching explicit and auditable.** Acceptance: read-only existing-transaction suggestions; owner and amount checks; idempotent accept/reject decision; reviewed observation immutability; no account balance mutation. Evidence: `supabase/migrations/20260929000060_document_confirmation.sql`, web `/api/documents/[id]/decisions`, and SQL tests.
- [x] **WEB-04 — Restrict extraction persistence to the server.** Acceptance: an authenticated client cannot submit OCR results or failures directly; the server must provide owner and current claim token; the migration and web route must be released together. Evidence: `supabase/migrations/20260929000070_document_provenance.sql` and web `/api/documents/[id]/extract`.
- [x] **WEB-05 — Capture historical Shortcut messages without duplicates.** Acceptance: private bounded batch intake, original timestamp and raw text preserved, idempotent replay, export/review, and read-only candidate search. Evidence: `supabase/migrations/20260929000030_shortcut_inbox.sql` and web `/transactions/shortcut-inbox`. The iOS setup guide is `spends-assistant-web/docs/guides/ios-shortcut-inbox-backfill.md`; Apple does not document the original receipt timestamp or stable message ID in the automation trigger, so unattended capture requires an on-device check.
- [x] **WEB-06 — Confirm and correct an existing transaction match from a Shortcut item.** Acceptance: explicit owner-scoped, replay-safe acknowledgement and append-only reversal; independently received notices can refer to the same real transaction; no financial mutation; hard deletion preserves a later active match. Depends on WEB-05. Evidence: migrations `20260929000080_shortcut_match_ack.sql` and `20260929000120_shortcut_match_reversal.sql`, web `/transactions/shortcut-inbox`, and PGlite tests. A reversed item cannot relink to the same transaction without a future versioned review token; created financial decisions use a separate correction flow.
- [x] **WEB-07 — Create a reviewed new transaction from an unmatched Shortcut item.** Acceptance: require deliberate category/account/amount/date confirmation, recheck bounded duplicate candidates within the database transaction, write the transaction and balance exactly once, and keep the original message plus decision provenance. Evidence: `supabase/migrations/20260929000110_shortcut_create_transaction.sql`, web `/transactions/shortcut-inbox`, and SQL/web tests. No automatic creation from an ambiguous Nequi recipient; multi-connection race and live Supabase behavior remain release checks.
- [x] **WEB-08 — Make CSV confirmation atomic.** Acceptance: owner-scoped idempotent import, recheck existing and within-batch duplicates at commit time, and one balance update per accepted row. Transfer rows without a destination and category/type mismatches fail before a financial write; category names resolve within each transaction type. Evidence: `supabase/migrations/20260929000020_atomic_csv_import.sql` and web import tests.
- [x] **WEB-14 — Make the existing AI request quota concurrency-safe.** Acceptance: text and OCR both consume the same request-count allowance through one atomic database operation; active pro remains unlimited; clients cannot reset the AI counter or promote themselves to pro. Evidence: `supabase/migrations/20260929000100_atomic_ai_parse_quota.sql` and PGlite tests. Multi-connection contention and remote grants still need staging verification. This is a request-count control, not a USD spending cap.
- [x] **WEB-15 — Make manual web transaction writes financially atomic.** Acceptance: owner-scoped creation, replacement, edit, and deletion keep transaction rows and account balances in one database transaction; active Pro bypasses the free transaction-count limit, and a request UUID supports creation replay. Reviewed document and Shortcut links block incompatible edits or deletion. Bulk editing permits only category, description, and notes, with category/type validation. Evidence: migrations `20260929000130_manual_transaction_atomic.sql`, `20260929000140_atomic_transaction_delete.sql`, and `20260929000150_atomic_transaction_patch.sql`, web transaction routes, and PGlite/web tests. Mobile direct upserts and real PostgreSQL contention remain separate release gates.

## Release 2: document coverage and financial context

- [ ] **WEB-09 — Benchmark and implement multi-page PDF statements.** Acceptance: synthetic page/row coverage and attribution gate passes before UI exposure; private bounded rendering, per-page retry state and page evidence, explicit overflow; no silent truncation. Depends on WEB-02–04. Focused Qwen 30B scored 15/21, 18/21, 21/21, and 16/21 across four full invented-document runs and therefore failed repeatability; see `docs/evaluations/2026-09-29-pdf-synthetic-focused-live.md` and `docs/plans/2026-09-28-multipage-pdf-statement-gate.md`.
- [ ] **WEB-10 — Evaluate semantic retrieval before pgvector backfill.** A synthetic eight-case benchmark improved the held-out correct first suggestion from 1/4 to 3/4, but its unmatched case still produced a false first suggestion. Acceptance: compare a larger consented labeled Spanish receipt/Nequi set with exact matching, confirm embedding-provider privacy, then implement owner-scoped versioned embeddings and bounded search only if useful; relational status and exact amount remain authoritative. Depends on WEB-03. See `docs/plans/2026-09-28-document-vector-search.md` and `docs/evaluations/2026-09-29-document-vector-synthetic.md`.
- [x] **WEB-11 — Add reviewed investment and loan journals.** Acceptance: owner-scoped Tyba/Binance positions and Lulo/Bancolombia loans with exact decimal amounts, replay safety, dated valuations/payment allocations, and no implicit impact on accounts or net worth. Evidence: migrations `20260929000040_manual_investments.sql` and `20260929000050_manual_loans.sql`, web `/investments` and `/loans`.
- [ ] **WEB-12 — Reconcile wealth with cash and net worth.** Acceptance: real opening statements and loan terms are reviewed, transfers and repayments do not double count, FX valuation is explicit, and each derived balance can be traced to ledger entries. Depends on WEB-11 and user-supplied figures.
- [ ] **WEB-13 — Review historic transaction quality.** Acceptance: present the private 1,516-row audit and 72 review signals, collect labeled corrections, evaluate prompt/category accuracy, and apply only approved edits with a reversible change log. Depends on the user's review. See `docs/audits/2026-09-28-transaction-quality-audit.md`.
- [ ] **WEB-16 — Establish account balance baselines before historic backfill.** Acceptance: review a dated opening or closing balance per account against a bank statement, decide which older transactions already contributed to the current stored balance, and prevent historical imports or Shortcut creation from double-counting cash. The read-only audit has no complete statement interval or opening balance, so the current account balances cannot be reconciled from its 1,516 rows alone. Depends on user-reviewed statements and WEB-13. See `docs/audits/2026-09-28-transaction-quality-audit.md`.
- [ ] **WEB-17 — Migrate mobile financial writes before enforcing database-wide invariants.** Acceptance: replace direct authenticated mobile transaction/account upserts and soft-deletes with compatible owner-scoped operations, then revoke broad direct financial write privileges. The current web RPCs make their own writes atomic but cannot prevent a direct authenticated client from editing its own financial rows. Depends on a reviewed mobile parity plan; see `spends-assistant-mobile/src/database/sync.ts`.
- [ ] **WEB-18 — Review the 2026 legacy Shortcut backfill before financial creation.** A local Scriptable companion exports the old message list without an API call, and an offline script prepares bounded inbox JSON from canonical messages and legacy `[Recibido: DD/MM/YYYY HH:mm]` strings, omitting messages present in a same-source inbox export. Acceptance: verify the actual iPhone export shape and original receipt timestamps for every bank, refresh the live 2026 transaction cutoff, test the released inbox with synthetic data, then review existing-transaction candidates and dated account balance baselines before creating only confirmed missing rows. Plain Bancolombia strings without receipt metadata must remain blocked. Evidence: `scripts/export-bulk.js`, `scripts/shortcut-backfill.mjs`, their `tests/scripts` cases, and `docs/plans/2026-09-29-shortcut-2026-backfill.md`.
- [ ] **WEB-19 — Link reviewed screenshots to investment and loan evidence.** Acceptance: upload a Tyba or Binance screenshot through the private image inbox, classify it as contribution, redemption, P2P buy/sell, or account settlement, show extracted fields against the manual investment or loan form, and require owner-scoped explicit confirmation before a journal event is created. Keep the source document and event linked for audit, reject inconsistent amounts/units, and never create a bank transaction implicitly. Start with synthetic images, then review consented real examples. Depends on WEB-02, WEB-11, and the no-double-counting design in WEB-12; see `docs/guides/investment-evidence-capture.md`.
- [ ] **WEB-20 — Bring Lulo email notices into the reviewed notification inbox.** Acceptance: a read-only mailbox export preserves stable message ID, message time, sender, subject, and plain text; a bounded local adapter prepares inbox batches under a distinct Lulo source; the web review detects candidate card purchases and card payments without direct financial writes; duplicate SMS/email/statement evidence can be linked to one event. Keep the Lulo credit card separate from the Lulo loan. The current Worker `/email` route is Bancolombia-only and must not be used for historical Lulo replay. The Google Apps Script exporter and generic email adapter are locally tested; a mailbox run, Lulo-specific classifier, and statement checks remain. See `docs/guides/lulo-gmail-backfill.md` and `docs/plans/2026-09-29-multisource-wealth-design.md`.
- [ ] **WEB-21 — Make credit-card screenshot OCR reviewable.** Acceptance: distinguish transaction rows from balance/minimum-payment summaries and zero-value statuses, preserve signed amount text and source excerpts, classify payments/fees/interest/insurance, group near-duplicate screenshots, and present ambiguous cross-image rows for explicit review. No OCR output may write a financial transaction or account balance. The private five-image benchmark exposed currency/date hallucinations and a validator failure for negative amounts; a card-specific draft improved row coverage but still needs original-resolution images and repeatable exact-field validation. See `docs/plans/2026-09-29-card-screenshot-ocr-design.md` and `docs/evaluations/2026-09-29-card-screenshot-live.md`.

## Release gate and mobile handoff

Before publishing web or database changes, run full tests, type checks, lint, web build, Worker dry run, SQL ownership/replay checks, and verify remote migration history with a backup. Obtain explicit approval for production migration and deployments. After the released web flows are stable, open mobile parity issues for document review, Shortcut intake, investment positions, and loans. Do not alter the existing mobile working tree during this web phase.
