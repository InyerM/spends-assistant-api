# Configurable document OCR and bounded vision fallback

Implementation update (12 November): the historical disabled-adapter boundary below is superseded by [the optional Mistral + DeepSeek release](2026-11-12-mistral-deepseek-review-release.md). The new route, consent, budget and provenance migrations are implemented locally; deployment remains pending. Nova fallback remains unimplemented.

Status: an isolated, disabled cloud-PDF adapter is implemented; endpoint rollout and vision fallback remain proposals, not published features. See the final section for the exact implemented boundary and unresolved gates. Defaults remain Qwen image vision and local-PDF-text → DeepSeek. No additional paid calls were made for this design or adapter. The hard-scan reports are frozen evidence, not a production model selection gate.

## Current architecture and capability

- Images: web `app/api/documents/[id]/extract/route.ts:93` calls Worker `/vision/extract` with a PNG/JPEG/WebP data URL. `src/handlers/vision-extract.ts:27` validates the image, requires owner authentication and `document_images` consent, increments parse allowance, then calls `src/ai/vision.ts:140`. The adapter uses Qwen 30B by default, Qwen 235B only with its internal escalation flag (the handler fixes it false), 2048 output tokens, `data_collection=deny`, and USD 0.40/1.00 per-million input/output caps (1.60 output when escalated). It does not currently enforce ZDR.
- PDFs: the web **already accepts PDFs** up to 5 MiB (`../spends-assistant-web/lib/documents.ts:31`). It downloads the private owner-scoped original and runs `readPdfText` in a bounded pdfjs worker. This extracts text; it does **not** rasterize or OCR. The worker limits 1–10 pages, 20k characters/page, 40k total, 20 seconds and 128 MiB old-generation memory (`../spends-assistant-web/lib/pdf-text.ts:29`). Any page below 20 characters produces `PDF_NO_TEXT`; passwords stay within local parsing.
- Web sends extracted `pages` to Worker `/documents/extract-text`, not the PDF bytes (`../spends-assistant-web/app/api/documents/[id]/extract/route.ts:76`). The Worker requires `financial_text` consent (`src/handlers/statement-text-extract.ts:31`). `src/ai/statement-text.ts:203` chunks and grounds DeepSeek responses to local text, at most 500 observations, with bounded workers and a 180-second deadline. Its `completeJson` path uses `provider.zdr=true` plus `data_collection=deny` (`src/ai/openrouter.ts:97`). The grounding depends on supplied source text, so it cannot simply validate an opaque end-to-end OCR result as if it were original local text.
- Extraction completes through owner/claim-scoped document RPCs in web; it returns drafts and never posts financial transactions. Keep these authority boundaries. `src/ai/vision.ts:91` checks field types but does not fully enforce its declared additional-properties schema, ISO dates, ISO currency codes or excerpt grounding. Existing web `parseExtraction` also tolerates extra fields via Zod stripping; provider `strict:true` alone is insufficient validation.

## Recommended shape and alternatives

Recommend an **explicit optional PDF OCR route**, isolated from existing image and PDF-text routes. A server-controlled capability `DOCUMENT_PDF_OCR_ENABLED=false` is the initial default. Add a discriminated server strategy `local_text` versus `mistral_ocr` and fixed allowlisted model IDs; the browser cannot choose arbitrary models, plugins, prices or provider privacy options. Enabling the capability alone must not automatically send an existing PDF to a new processor. An explicit OCR extraction action and valid OCR consent are required. `PDF_NO_TEXT` should remain a clear local result with an eligible OCR action, rather than silently changing processors.

Alternative A: whole PDF → Mistral OCR plugin → DeepSeek, matching the successful three-page benchmark. This is simplest but cannot establish trustworthy page provenance from the current documented annotation schema, and has single-request truncation/timeout risks. Alternative B: locally split a bounded PDF into single-page PDFs → OCR plugin → DeepSeek per page, assigning page index before dispatch; this is recommended for production provenance. It requires a safe PDF splitter in the deployed web runtime (only pdfjs is currently present), bounded memory and end-to-end page-completion state. Alternative C: locally render pages → image model avoids the OCR plugin but needs a proven deployed renderer; current web has no such renderer. Do not conflate B or C with existing text extraction.

Start the implementation as backend adapter tests and disabled capability; release only after page ownership/completion/provenance support exists. Initial proposed OCR limits: 5 MiB original, 1–5 pages, 50 observations/page and 250/document, with explicit overflow errors. These are new route limits, not changes to the existing 10-page/500-row text path. Reject malformed/encrypted inputs in the OCR path; never forward a password or use public/signed document URLs. A future separate local decrypt-and-reserialize feature needs its own evidence and transient-memory design. Use base64 Chat Completions file parts and an explicit `file-parser` / `mistral-ocr` engine. Reject unsupported environments rather than assuming Cloudflare Workers can execute native PDF tooling.

## Nova fallback: technical failures only

A separate `VISION_TECHNICAL_FALLBACK_ENABLED=false` controls one secondary Nova 2 Lite attempt, preserving the primary model. The setting must be server-owned and require its own configured price ceilings; the current USD 1.00/1.60 output caps do not permit Nova's observed USD 2.50/M output price. Do not widen existing caps implicitly.

Classify failures with a typed adapter error. Recommended eligible set: network/timeout, 408/429/500/502/503/504, malformed provider envelope, missing completion, truncation, invalid JSON, or full structural-schema violation. These are observable transport/output-contract failures, not judgments of extraction quality. Normalize only a complete enclosing JSON Markdown fence before schema validation, so a valid Nova fence does not trigger another call. If a narrower definition of technical is desired, omit output-contract failures; default recommendation is the explicit allowlist above. Never fallback for low confidence, null amount/date/currency, zero observations, plausible wrong signs/dates, missing evidence, refusal, authentication/configuration failure, consent denial, allowance exhaustion, unsupported MIME, permanent 4xx or privacy/price incompatibility. No retries after Nova, no model arrays or provider-level cross-model fallback, no fallback loop, and an end-to-end deadline bounds both attempts.

Validate both responses against the same full local schema: exact required/allowed keys, nullable finite bounded amount, 3-letter supported currency or null, valid calendar ISO date or null, bounded text, confidence [0,1], array ceilings, and explicit rejection of truncation. Preserve uncertain evidence for human review. Technical fallback does not remedy semantically wrong but structurally valid rows and must not claim to. Keep literal printed sign evidence separate from cash-flow amount semantics: production vision intentionally makes purchases negative (`src/ai/vision.ts:169`), while the hard challenge scored literal signs. Introduce explicit raw amount/direction evidence only through a deliberate contract/version and review UI plan, not an accidental prompt transplant.

## Consent, privacy and official capabilities

Recommend a new **document_ocr** consent scope plus versioned disclosure naming OpenRouter, Mistral OCR and the downstream inference provider. Existing `financial_text` consent covers extracted text and cannot be assumed to authorize sending the original PDF to an additional processor; `document_images` alone also does not establish informed OCR consent. Preserve existing scope decisions rather than blanket-invalidating them. Recheck consent after authentication and before each external dispatch, fail closed on consent-store failure, and keep original bytes/annotations out of logs and telemetry.

[OpenRouter PDF documentation](https://openrouter.ai/docs/guides/overview/multimodal/pdfs), checked 2026-11-11, supports base64 file parts, explicit parser selection and reusable parsed annotations. Mistral OCR forwards at most eight extracted images, preserving extracted text; annotations can contain sensitive text/images. For phase one, keep annotations transient and avoid reuse/persistence until its privacy and cost accounting are designed. Do not use the persistent Files API.

[OpenRouter ZDR documentation](https://openrouter.ai/docs/guides/features/zdr), checked 2026-11-11, explicitly limits ZDR enforcement to inference routing, excluding plugins/tools; account settings may also allow Safety Retention endpoints. Neither `zdr:true` nor `data_collection=deny` establishes plugin retention. Current Mistral OCR-specific retention/region terms are **not independently established** by this design. Real-data enablement therefore requires a documented plugin policy and appropriate consent/disclosure; synthetic success does not waive it. Do not advertise end-to-end ZDR.

## Costs, telemetry and acceptance gates

The hard benchmark observed USD 0.00680891 for three scanned pages plus DeepSeek, of which upstream inference was USD 0.00080891; the difference USD 0.006 matches the documented OCR page charge. Nine image calls cost USD 0.0054183. These are small synthetic observations, not production estimates or monthly ceilings ([evidence](../evaluations/2026-11-11-hard-scans.md)). Model prices must be revalidated on enablement; Nova's cap mismatch is explicit. Reserve per-page OCR charges plus maximum bounded inference/fallback budget before dispatch, track actual total usage cost once (avoid adding plugin fees twice), and mark missing usage cost unknown. A timeout may still be billed: reserve both attempts and never assume a failed call was free.

`AiUsageService.track` currently associates one meter summary with one model label (`src/services/supabase/ai-usage.service.ts:49`). Fallback would otherwise attribute both calls to the primary; add attempt-level model/pathway attribution while retaining one user parse allowance per extraction action. OCR page fan-out must count all upstream calls and costs, not charge the user's parse quota once per page. Log only safe error category, model/pathway, latency, counts and cost; never PDF content, passwords, prompts, excerpts or annotation payloads.

Acceptance tests first: default requests remain unchanged; flag off blocks new pathway; owner/claim checks; consent-before-dispatch; server-fixed IDs/caps; malformed/encrypted/oversized/page-overflow inputs; strict/fenced JSON matrix; allowlisted technical fallback only; every semantic uncertainty stays review-only; both attempts metered with actual model; no retries after secondary; total deadline/cost reservation; all-page completion/provenance and duplicate boundary rows; no observation overwrite after audited review; no financial posting. Deployment-runtime proof for splitting/rendering, repeated paired clean/degraded synthetic tests, independent ground-truth review and separately consented real-document evidence are required before any default-change proposal.

## Implemented boundary after plan review

Only the isolated `src/ai/cloud-pdf-ocr.ts` adapter and `tests/ai/cloud-pdf-ocr.test.ts` were implemented. There is no route import, environment change, consent migration, frontend change or publication. `cloudPdfOptIn` must be exactly true; omission is disabled. This internal boolean is **not consent** and is deliberately insufficient for a future public endpoint. The caller must establish a newly disclosed OCR permission and supply trusted bounded-parser inspection (SHA-256, 1–5 pages, unencrypted), never browser assertions. The adapter binds an immutable byte copy to that hash, verifies PDF signature and 5 MiB ceiling, and refuses encryption/page overflow before dispatch; it does not itself parse PDF structures or establish inspection truth.

The fixed cloud pathway uses Mistral OCR plus DeepSeek, `zdr:true` and `data_collection=deny` for inference routing, with no retries, automatic model fallback, default selection or financial posting. A complete JSON fence may be normalized, then exact schema/type/calendar/length/array validation applies. An empty or uncertain response remains `requiresReview:true`, as does every successful draft. Known incoming/outgoing directions must agree with the normalized cash-flow sign; contradictory pairs are rejected. This does not prove that the direction or amount matches the source. Strict schema cannot detect other plausible wrong financial facts or prove complete row coverage; no such claim is made. Responses are streamed with a 256k-byte ceiling; upstream bodies/errors are never logged or attached to errors. The adapter records supplied total cost once, including on invalid draft output, without adding assumed OCR fees.

The predispatch budget uses conservative inference ceilings USD 0.40/1.00 per million tokens, an estimated 50k-input-token allowance, 4096 output tokens and USD 0.01/page OCR allowance. Three pages reserve USD 0.054096. These are **local conservative estimates, not a provider-enforced hard bill cap**; raw compressed PDFs can expand substantially. There is no atomic account-budget reservation/charge ledger in this isolated adapter. Before public wiring, add verified resource/token bounds and atomic budget accounting (including concurrent page attempts), or explicitly reject workloads without a trustworthy upper bound. A future OCR endpoint must remain blocked while this spending guard, trusted inspection/provenance and new consent/plugin retention disclosure are unresolved.

Nova exists only as a measured benchmark candidate. The earlier fallback design is a proposal, **not implemented**; no Nova fallback is connected to OCR or any production route. Future endpoint contract should accept an owner-scoped document ID plus an explicit cloud OCR action, never arbitrary PDF URLs, model names, client inspection, prices or a bypass-consent flag. The server resolves private bytes, validates fresh OCR consent, checks capability and budget, claims the document, invokes bounded inspection/extraction, and completes drafts through existing owner/claim RPC authority. Keep local text and image extraction behavior unchanged until those gates are resolved.
