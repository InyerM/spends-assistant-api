## Local verification and release order

1. Finish and review all local branch integrations. Keep every migration in timestamp order. Do not edit already applied remote migrations.
2. Run complete backend and web tests, type checks, lint, a production web build, a Worker dry run, and SQL assertions. PGlite tests exercise the new functions, but the Docker-backed full Supabase stack is unavailable on this machine.
3. Review the private proposal JSON outside Git and prepare a backup of the resumed Supabase project. Verify the linked project and migration history before any remote database change.
4. With explicit release approval, apply migrations first, set the OpenRouter production secret, deploy the Worker, then deploy the web app. A push to backend `main` triggers the Cloudflare deployment workflow, so local commits alone do not publish anything.
5. Smoke test each authenticated workflow with synthetic data, then ask the user to review real documents and historical messages. Do not upload personal data to model evaluations without a separately reviewed sample.
6. Start mobile parity only after the corresponding web flows and data contracts are stable; preserve its existing uncommitted work.

The US$10 per person per month figure is an internal planning estimate. It is not a product cap or a reason to reject a request. Compare observed provider costs with the model price sheet and monthly workload after the local telemetry migration is running in an approved environment.
